## 2. Defects found in this pass (each had a test that failed first)

1. CI validated `docs/spec/DFL_Design_Document_Ed8.54.md`, which does not exist (the repository holds Ed8.61): the step could never pass. Fixed (`ab87c22`).
2. CI's checkout fetched one commit; tests read the pinned candidate and release trees by hash and could never pass there. Fixed: `fetch-depth: 0`.
3. Three tests in `test_vtest_v0.py` raised `ModuleNotFoundError` under CI's own command (`from tests.test_vtest import ...`). Fixed.
4. The installer had no end-to-end test; two earlier failures (`KeyError 'ETC'`, missing probe folder) got through because tests used hand-built inputs. New tests run `render.install` whole; each earlier failure is reproduced by a mutant and caught. The rehearsal found **no new installer defect** (two early failures in the rehearsal's own checks were mistakes in the checks, corrected).
5. **GitHub CI run 43050999661** (the first run observed on this branch; it ran 1 h 21 min and failed) showed two defects invisible on a root shell with every package installed. Both were reproduced as an unprivileged user with only numpy before any fix, and neither is in the code under test:
   * `tests/test_reveal_real.py` could not be imported: `tools/measure_combined.py` imports `psutil` at module level and CI installed only numpy. Fix: `requirements-test.txt` (psutil), installed by CI; new test `test_ci_config.CiDependencies` fails if a test file reaches a third-party module at import time that no installed requirements file names (it failed on `psutil` first).
   * Eight `test_site_deploy.Install` tests failed because the installer's `chown` is refused to a non-root user. Fix: recording stand-ins for `chown` and `runuser` in the test's scratch `bin/` (as for `caddy` and `systemctl`); the good-install test now also asserts that the feed folder is handed to the service user. The one test that needs the real ownership change and user switch removes the stand-ins and still skips without root (explicit skip, listed in section 4). Reproducing it also showed that, run by an unprivileged user without `runuser` on the path, the script falls back to `su` and waits for a password; the stand-in avoids that.
